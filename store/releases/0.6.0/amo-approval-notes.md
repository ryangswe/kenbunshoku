Kenbunshoku 0.6.0 recognizes trading cards in video frames, in the browser. To try it: open a One Piece Card Game video on www.youtube.com or www.twitch.tv, for example https://www.youtube.com/watch?v=2e4cdU4YDY4&t=811s, pause it, and rest the pointer on a card in the picture; the card's picture appears beside it. On a YouTube watch or live page, and on a Twitch channel's page, past broadcast or clip, the extension loads its recognition model when the page's main video plays; elsewhere, and for a video that has not played, it loads at the first pointer move over the video. Loading reads no picture: the video's picture is read only around the user's pointer activity over it. When the model loads, the extension downloads from cdn.kenbunshoku.com the newer card-data release the settings file names: its card list and card fingerprints (JSON, a few MB; the models are the packaged ones). At the first pointer over the video it also downloads a card-feature data file of about 60 MB (used only where WebGPU is available) and caches it. Card pictures come from cdn.kenbunshoku.com or optcgapi.com.

New since 0.5.0: the recognition runtime is the open-source cardvision toolkit's browser package at tag v0.14.0rc2 (https://github.com/ryangswe/riftsight-vision, browser/ folder), vendored unmodified; the source archive includes it. The changes are in when the video's picture is looked at (pacing, retries, one look when a slow load ends under a resting pointer) and in when card hovers start. It asks for no new permissions, stores no new settings and contacts no new hosts. Card hovers start in two more cases (switching them back on after an idle unload, and the video playing again after the page removed the extension's frames), making only the requests the privacy policy already lists.

The scripts are minified with esbuild. The attached source archive rebuilds the package's files exactly: unzip it and run ./build-firefox.sh (Node 22+, npm, zip; README.md inside has the steps), then compare the files in out/'s zip with the uploaded package (the zip's own timestamps differ). The linter's two warnings about the Function constructor (runtime/ort-wasm-simd-threaded.jsep.mjs line 52, runtime/worker.js line 1862) are in ONNX Runtime Web 1.29.0 (onnxruntime-web on npm, Microsoft, MIT), which the extension bundles to run its recognition models. Its two warnings about dynamic import (runtime/worker.js lines 1 and 1864) are ONNX Runtime Web loading its own packaged module and the runtime loading the packaged OpenCV.js (runtime/opencv.mjs); both import files inside the package only. The WebAssembly files are ONNX Runtime's and OpenCV.js 5.0.0's, unmodified. The extension downloads data only (card pictures; a settings file checked against its schema; JSON release files, card fingerprints and card lists, ONNX models and binary card features checked against SHA-256 values); it never runs downloaded code.
