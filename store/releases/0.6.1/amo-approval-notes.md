Kenbunshoku 0.6.1 recognizes trading cards in video frames, in the browser. To try it, open a One Piece Card Game video on www.youtube.com or www.twitch.tv (for example https://www.youtube.com/watch?v=2e4cdU4YDY4&t=811s), pause it and rest the pointer on a card in the picture. The card's picture appears beside it. On a YouTube watch or live page, and on a Twitch channel's page, past broadcast or clip, the recognition model loads when the page's main video plays. Elsewhere, and for a video that has not played, it loads at the first pointer move over the video. Loading reads no picture; the picture is read only around pointer activity over the video. When the model loads, the extension downloads from cdn.kenbunshoku.com the newer card-data release the settings file names (a card list and fingerprints in JSON, a few MB; the models are packaged). At the first pointer move over the video, it also downloads and caches a card-feature file of about 60 MB, used only where WebGPU is available. Card pictures come from cdn.kenbunshoku.com or optcgapi.com.

In 0.6.1, the recognition runtime is the open-source cardvision toolkit's browser package at tag v0.14.1 (https://github.com/ryangswe/riftsight-vision, browser/ folder), vendored unmodified and included in the source archive. The one change is in when the picture is read. When the model finishes loading while the pointer rests over the video, the extension no longer misses the one picture it may then read when its hidden frame first connects late or when loading ends just before the pointer's first 10 seconds are over. The load adds at most one picture, within 60 seconds of the pointer's last move. If it shows a card, pictures are read while the card shows, as for any card; if not, nothing more is read after those 10 seconds until the pointer moves. The privacy policy says so. Version 0.6.1 adds no permissions, settings or hosts.

The scripts are minified with esbuild. The attached source archive rebuilds the package's files exactly. Unzip it and run ./build-firefox.sh (Node 22+, npm, zip; see its README.md), then compare the files in out/'s zip with the uploaded package (the zip's own timestamps differ). The linter's two Function constructor warnings (runtime/ort-wasm-simd-threaded.jsep.mjs line 52, runtime/worker.js line 1862) are in ONNX Runtime Web 1.29.0 (onnxruntime-web, Microsoft, MIT), which the extension bundles to run its models. Its two dynamic import warnings (runtime/worker.js lines 1 and 1864) are ONNX Runtime Web loading its own packaged module and the runtime loading the packaged OpenCV.js (runtime/opencv.mjs). Both import files inside the package only. The WebAssembly files are ONNX Runtime's and OpenCV.js 5.0.0's, unmodified. The extension downloads only data (card pictures, a settings file checked against its schema, and JSON release files, card fingerprints, card lists, ONNX models and binary card features checked against SHA-256 values). It never runs downloaded code.
